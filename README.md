# 로또 6/45 분석 · 번호 생성기

과거 당첨번호로 "예측 전략"이 실제로 통하는지 검증하고, 이번 회차 번호를 골라 주는 도구입니다.
파이썬 3.10 이상의 표준 라이브러리만 사용합니다.

```bash
python -m lotto update     # 동행복권에서 전 회차 당첨번호를 data/draws.csv 로 내려받기
python -m lotto analyze    # 번호별 빈도, 균일성 검정, 예측 전략 백테스트
python -m lotto pick       # 이번 주 회차 번호 5게임 생성 (--games, --draw, --seed)
python -m lotto plan       # 2장 + "줄마다 2개 이하" 가정으로 고른 3장째 (--line 으로 이미 산 번호 입력)
python -m lotto sim        # 줄마다 자동 1,000장 시뮬레이션 → 가장 적게 나온 4개 + 중간 2개, 5줄 = 1장 (--sheets, --seed)
python -m lotto ratio      # 최근 1~5등 당첨자 비율 분석 + 그 비율에 맞는 1장 (--prizes, --seed)
python -m unittest         # 테스트
```

## 웹 버전

`web/index.html`은 설치나 다운로드 없이 브라우저에서 `ratio`와 같은 방식으로 번호 1장을 뽑는 페이지입니다.
파일을 브라우저로 열면 되고, 휴대폰에서도 동작합니다. 판단 로직(패턴 필터, 등수별 기대값)은 파이썬 쪽과 같습니다.

## 실행파일

파이썬 없이 쓰는 실행파일은 GitHub Actions가 푸시할 때마다 Windows·macOS·Linux용으로 만듭니다.
저장소의 **Actions → Build executables → 최근 실행 → Artifacts**에서 `lotto-Windows` 등을 내려받아 압축을 풉니다.

- **더블클릭**하면 `ratio`(최근 1~5등 비율 분석 + 그 비율에 맞는 번호) 1장이 나오고, 엔터를 누르면 다시 뽑고 `q`를 누르면 종료합니다.
- 명령 프롬프트·터미널에서는 `lotto pick`, `lotto plan`, `lotto update`처럼 위 명령을 그대로 쓸 수 있습니다.
  `update`로 받은 당첨 이력은 실행파일 옆 `data` 폴더에 저장됩니다.
- 코드 서명 인증서가 없는 실행파일이라 경고가 뜰 수 있습니다.
  - Chrome이 다운로드를 막으면 `chrome://downloads`에서 해당 파일의 **계속** 또는 **위험한 파일 다운로드**를 누르세요.
  - Windows에서 "PC 보호" 창이 뜨면 **추가 정보 → 실행**을 누르세요.
  - macOS에서는 **우클릭 → 열기**를 누르세요.
  - 경고 없이 쓰려면 위의 웹 버전을 쓰세요.

직접 만들려면 `pip install pyinstaller` 후 `pyinstaller --onefile --name lotto lotto_app.py`를 실행하면 `dist/`에 생깁니다.
(PyInstaller는 실행하는 OS용 파일만 만듭니다.)

## 먼저 알아둘 점

로또 추첨은 매번 독립적인 균등 추첨이라, 어떤 조합이든 1등 확률은 **1/8,145,060**으로 같습니다.
과거 데이터로 다음 번호를 맞히는 모델은 원리상 무작위로 찍는 것보다 나을 수 없습니다.
`analyze`는 이를 직접 확인할 수 있게 해 줍니다.

- **균일성 검정**: 번호별 출현 횟수가 균등 추첨에서 기대되는 범위 안에 있는지 카이제곱 검정합니다.
  한 회차에 서로 다른 6개가 뽑히는 점을 반영해 통계량을 (N-1)/(N-K)배 보정합니다.
- **백테스트**: 최근 300회를 그 이전 이력만으로 예측해 1게임당 평균 일치 개수를 봅니다.
  어떤 번호를 고르든 이론 기대값은 0.8개, 3개 이상(5등 이상) 확률은 2.38%입니다.
  - `hot`: 최근 50회에 많이 나온 번호
  - `cold`: 가장 오래 안 나온 번호
  - `weighted`: 전체 출현 빈도에 비례해 추첨
  - `random`: 무작위 (비교 기준)

## `pick`이 하는 일

당첨 확률은 못 바꾸지만, **당첨됐을 때 상금을 나눠 가질 사람 수**는 번호 선택에 따라 달라집니다.
사람들은 생일(1~31), 연속 번호, 일정한 간격, 용지 위의 줄 모양, 지난주 번호를 많이 고르기 때문입니다.
`pick`은 균등하게 뽑은 조합 가운데 아래에 해당하는 것을 버립니다(전체 조합의 약 57%가 통과).

- 31보다 큰 번호가 2개 미만
- 연속 번호 3개 이상
- 등차수열 4개 이상 (예: 5, 10, 15, 20)
- 용지(7칸 × 7줄)의 같은 가로줄이나 세로줄에 4개 이상
- 과거 1등 조합 그대로, 또는 지난 회차 번호와 3개 이상 겹침 (`update` 후에만 적용)

또한 여러 게임끼리 겹치는 번호가 2개를 넘지 않게 해서 게임마다 다른 번호를 고르게 합니다.

## `plan`: 2장 산 뒤 3장째 고르기

5,000원짜리 2장(10줄)을 사고, "10줄 모두 2개 이하로만 맞는다"고 가정해 그 가정과 맞지 않는 조합,
즉 어느 한 줄과라도 3개 이상 겹치는 조합을 1등 후보에서 뺍니다. 3장째 5줄은 남은 조합에서만 고릅니다.
이미 산 번호가 있으면 `--line "5 14 27 29 32 40"`처럼 줄마다 넣으면 됩니다.

실행하면 이 가정이 확률을 어떻게 바꾸는지 함께 보여 줍니다. 예를 들어 10줄이면 대략 이렇습니다.

| 경우 | 확률 | 3장째 1줄의 1등 확률 |
|---|---|---|
| 가정이 맞음 (10줄 모두 2개 이하) | 약 78% | 약 1/6,370,000 |
| 가정이 틀림 (어느 줄이 3개 이상 = 5등 이상 당첨) | 약 22% | 0 |
| 합계 | | 1/8,145,060 (그대로) |

후보를 줄인 만큼 가정이 틀릴 위험을 지기 때문에, 3장째 한 줄의 1등 확률은 그대로입니다.
3장 전체로는 15줄 × 1/8,145,060입니다. 이 방식으로 달라지는 점은 15줄끼리 번호가 2개 넘게 겹치지 않는다는 것입니다.

## `sim`: 자동 구매 시뮬레이션으로 1장 만들기

한 줄을 만들 때마다 자동(무작위) 번호로 1,000장(5,000줄)을 새로 산다고 가정하고 번호별 출현 횟수를 셉니다.

1. 가장 적게 나온 번호 4개
2. 45개를 횟수 순으로 세웠을 때 가운데(22·23번째)에 있는 번호 2개
3. 4개 + 2개 = 1줄. 이 과정을 5번 반복해 5,000원짜리 1장(5줄)을 만듭니다.

자동 번호는 균등 무작위라 시뮬레이션에서 적게 나온 번호도 우연일 뿐이고, 실행할 때마다 달라집니다.
각 줄의 1등 확률은 다른 조합과 같은 1/8,145,060입니다.

## `ratio`: 최근 1~5등 당첨자 비율에 맞는 번호

최근 회차의 등수별 당첨자 수를 무작위 조합의 기대값과 비교합니다. 내장된 최근 5회 기준:

| 등수 | 평균 당첨자 | 무작위 조합 기대값 | 관측/기대 |
|---|---:|---:|---:|
| 1등 | 13.0 | 15.1 | 0.86 |
| 2등 | 90.8 | 90.8 | 1.00 |
| 3등 | 3,396 | 3,449 | 0.98 |
| 4등 | 167,437 | 168,124 | 1.00 |
| 5등 | 2,765,450 | 2,764,708 | 1.00 |

한 게임이 각 등수에 해당하는 조합 수는 1 : 6 : 228 : 11,115 : 182,780으로 정해져 있어서,
당첨자 비율은 당첨번호와 상관없이 이 비율 × 판매량(회당 약 1.23억 게임)이 됩니다.
1등만 기대값보다 적은 것은 수동 구매가 일부 조합에 몰려 있다는 뜻이고, 그런 조합이 당첨되면 1등이 훨씬 많이 나옵니다.
그래서 이 비율에 맞는 번호는 사람들이 많이 고르는 패턴을 뺀 조합이며, `pick`과 같은 필터로 1장(5줄)을 고릅니다.

새 회차 결과를 넣으려면 `data/prizes.csv`(실행파일은 옆의 `data` 폴더)를 아래 형식으로 만들면 내장 데이터 대신 씁니다.

```
first,second,third,fourth,fifth,auto,manual,semi_auto
16,64,3350,155108,2608922,11,4,1
```
